# 椰果排队弹幕自动获取工具

面向 Windows 11 和 OBS Studio 的 B 站直播排队工具。程序使用 C 编写，监听指定直播间的弹幕与礼物事件；观众发送完全匹配的「排队」后进入名单，送出「粉丝团灯牌」可获得队首优先。浏览器源显示千咲主题队列面板，管理页可手动加人、删人和调节字号。

## 给其他主播使用：修改直播间号

首次使用、采用默认匿名模式时，**只需把 `config.json` 中的 `room_id` 改成自己的 B 站直播间号，然后启动程序**；不必改 C 源码，也不必安装 Python 库。该值是直播间号，不是用户 UID。程序启动后，控制台首页会显示当前监听的直播间号，供你核对。

但有两点需要注意：

- 匿名连接可能只收到 B 站脱敏用户名，例如 `你***`。若需要完整名字，可选择在**自己的电脑**上配置自己的 B 站登录态，详见下文；仅改 `room_id` 不能保证解除脱敏。
- 如果是在同一安装目录里切换直播间，旧队列保存在 `data/state.json`，不会因改 `room_id` 自动清空。请先备份需要的记录，再用管理页清空队列；若想连待用灯牌记录也一起重置，应在程序完全退出后另行处理该本地状态文件。全新下载的项目不会带有他人的状态文件。

`config.json` 示例：

```json
{
  "room_id": 1881592284,
  "keyword": "排队",
  "priority_gifts": ["粉丝团灯牌"],
  "port": 8765,
  "font_size": 36,
  "max_rows": 50
}
```

其他配置：`keyword` 是必须完全匹配的入队弹幕；`priority_gifts` 目前只读取列表中的第一个礼物名称；`port` 是本地网页端口；`font_size` 是无已保存状态时的初始字号；`max_rows` 是 OBS 最多显示的人数。修改配置后需重启程序。管理页改过的字号会保存在状态文件里，并在重启后覆盖初始字号。

## 功能与排队规则

- 用户发送完全匹配的 `排队`：加入队尾；同一可识别用户不重复入队。
- 已在队列的用户送出 `粉丝团灯牌`：移到第 1 位，其他人依次后移。
- 用户先送灯牌、后发 `排队`：先记录待用优先资格，入队时插到第 1 位。
- 队列、字号和待用灯牌资格保存在本机 `data/state.json`，重启后恢复。匿名脱敏事件的身份匹配受 B 站提供的数据限制，不能保证与登录态一样准确。
- OBS 页面在后端断开后会自动隐藏整个面板，服务恢复后重新显示。

## 环境、编译和启动

- Windows 11；OBS Studio 用于直播画面显示。
- 使用 GCC（MinGW-w64）编译 C17 程序。项目不需要 Python、pip 或 Node.js。
- 构建脚本期望本机有 `C:\mingw64\bin\zlib1.dll`；若你的 MinGW 安装位置不同，请调整 `build.bat` 中复制 DLL 的路径。网络与加密主要使用 Windows 自带的 WinHTTP、WinSock 和 BCrypt。

在项目目录运行 `build.bat`，得到 `build\queue_overlay.exe`；再运行 `start.bat`。后续如果仅修改 `config.json`，无需重新编译，重新启动即可。直播期间请保持程序窗口运行。

**已有编译好的程序时，不必安装 GCC：** 保留 `build\queue_overlay.exe` 和同目录的 `build\zlib1.dll`，同时保留项目根目录的 `config.json`、`static/` 等文件，然后从项目根目录运行 `start.bat`。不要只拷走 exe，也不要直接在 `build/` 目录内以错误的工作目录运行。当前源码仓库通过 `.gitignore` 排除了 `build/`，所以单纯克隆仓库的人不会得到预编译 exe，仍需自行编译；预编译发布包若另行提供，应包含 exe、DLL、配置和静态资源。

若页面没有打开，可以手动访问：

| 用途 | 地址 |
| --- | --- |
| 管理页 | `http://127.0.0.1:8765/`（`/control` 也可用） |
| OBS 浏览器源 | `http://127.0.0.1:8765/console`（`/overlay` 为兼容地址） |

若更改 `port`，上述地址中的 `8765` 也要同步更改。服务仅监听本机 `127.0.0.1`，并非对外托管网页。

## OBS Studio 设置

在“来源”中添加“浏览器”，地址填 `http://127.0.0.1:8765/console`。建议初始尺寸 `800 × 1200` 或其他 `2:3` 比例，再根据场景缩放定位。千咲主题装饰框外侧透明、内部为深红黑色底板；用户名行以浅色和深色块交替显示。管理页不要作为 OBS 浏览器源。

网页每 500 毫秒检查一次后端。程序退出后连续两次连接失败，队列面板便会隐藏；重新启动会自动恢复。如果 OBS 仍保留旧画面，请在浏览器源上手动点击一次“刷新”，使其加载最新版前端脚本。

## 管理命令

管理页和程序终端均可输入：

| 命令 | 作用 |
| --- | --- |
| `del-3` | 删除第 3 位，后面名次自动递补 |
| `add-你好` | 手动加入队尾 |
| `add-你好-3` | 插入第 3 位；同名手动用户已存在时改为移动 |
| `font-42` | 设置 OBS 队列字号为 42px（范围 12–160） |
| `list` | 查看当前队列 |
| `clear` | 清空队列；不清除待用灯牌资格 |
| `help` | 查看程序内的命令帮助 |

管理页还提供字号滑块、逐行删除按钮，以及未开播时的本地模拟按钮。模拟只改变本地队列，**不会向 B 站发送弹幕或礼物**。例如在终端依次输入：

```text
test-queue-我是hello
test-queue-我是hi
test-gift-我是hi
```

预期名次为 `1 → 我是hi`、`2 → 我是hello`。

## 完整用户名与本地登录态（可选）

B 站匿名连接可能把普通用户显示为 `UID=0` 和脱敏昵称。要尝试获取完整用户名，可复制 `auth.example.json` 为本地 `auth.json`，在你自己的已登录浏览器中取得 `live.bilibili.com` 的 Cookie，填写 `SESSDATA`、`DedeUserID`、`buvid3`，并把 `uid` 设为 `DedeUserID` 的数字值、`buvid` 设为 `buvid3`，然后完全退出并重启程序。此方式依赖 B 站当前接口与账户状态，不能保证一直有效。

**不要在 issue、聊天、截图、直播画面或 Git 仓库中公开 Cookie。** `auth.json`、`data/` 和 `build/` 已列入 `.gitignore`。程序不会通过本地网页 API 返回 Cookie，但本机登录态仍应妥善保管。若不需要完整用户名，不创建 `auth.json` 即可使用匿名模式。
